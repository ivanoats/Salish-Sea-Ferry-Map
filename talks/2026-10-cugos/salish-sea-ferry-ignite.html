Hi, I'm Ivan. I'm a transportation nerd: give me a good transit map and I'll stare at it longer than is reasonable. This talk is about a map I wanted, couldn't find, and built.

A bike-and-ferry loop

Seattle → Bainbridge → (bike) Kingston → Edmonds

Whose boats? Which docks? What are all my options?

I plan a lot of bike-and-ferry trips. Ferry to Bainbridge, ride north to Kingston, ferry to Edmonds. A simple loop. But I wanted to see every option at once, across every agency.

The answer today

23 operators. 23 websites.

    That's harder than it sounds. Twenty-three operators run boats on this water, from WSF and BC Ferries down to a pub that runs its own boat to Protection Island. Each one maps only its own routes.

    The stack

    All open, all boring (good).

    MapLibre GLrendering
    OpenStreetMapbasemaps and route geometry
    GeoJSONthe routes
    Next.js + TypeScriptthe wrapper, on Netlify
    The stack is open and boring, in a good way. MapLibre GL renders it, OpenStreetMap underneath, and plain GeoJSON for the routes. Next.js and TypeScript wrap it, and Netlify hosts it.

    The data

    Hand-curated.
    Checked against GTFS.

    Some operators publish no feed at all. Where feeds exist, they're pinned and used at build time to check the data, not replace it.

    Some operators publish no machine-readable feed at all, so the dataset is hand-curated. Where GTFS feeds do exist, like WSF and BC Ferries, they're pinned and used at build time to check my data, not replace it.

    Then I audited every terminal against OpenStreetMap. Seventeen were off, some by half a mile. Langdale was sitting out in Howe Sound. Every one is now on its dock, with its OSM node ID cited.

    Lines over water

    Routes follow
    the water.

    85OSM ferry routes

    Early versions drew straight lines between docks, right across islands. Now all eighty-seven legs follow the water: eighty-five from OSM ferry routes, two from a navigable-water mesh, and zero straight lines.

    How · scripts/build-route-geometry.ts (condensed)

    A fallback chain.

    const osm = osmRouteCoordinates(osmGraphs, from, to);
if (osm !== null) {
  geometry.set(key, { source: "osm", coordinates: osm });
  continue;
}

const mesh = meshPathCoordinates(waterMesh, from, to);
if (mesh !== null) {
  geometry.set(key, { source: "mesh", coordinates: mesh });
  continue;
}

// last resort, and the count on the last slide was zero
geometry.set(key, { source: "straight", coordinates: [from, to] });

    Baked at build time. Neither dataset ships to the browser.

    The trick is a fallback chain. Prefer OSM's mapped ferry route. If there isn't one, use a water mesh borrowed from my sailing route planner: OSM's coastline drawn on an 80-metre grid and flooded from the Pacific. Straight lines only as a last resort.

    Tests for cartography

    The build fails if…

    • a leg leaves the 45° grid
    • a route crosses land
    • an island's terminal lands in the water
    • a line runs through a stop it doesn't make
    And the diagram has tests. The build fails if a leg leaves the forty-five-degree grid, if a route crosses land, if an island's terminal ends up in the water, or if a line runs through a stop it doesn't make.

    Print

    A web map is not
    a print map.

    Teewhole diagram · 3600 × 4800 px at 300 DPI
    Totecropped to Puget Sound, or the labels print at 4 pt
    Print turned out to be its own problem. The diagram renders as 300 DPI print files for a tee and a tote. The tote is cropped to Puget Sound, because the full diagram would print its labels at four points.

    The live layer

    No API key? The layer turns off and the map still works.

    WSF is the one operator with a public vessel API. A small server proxy pulls positions from WSDOT and shows live boats. Without an API key, the layer turns off and the map still works.

    Scope

    A route map,
    not a trip planner.

    No schedules. No fares. On purpose. The operators already publish those, and they change constantly.

    One thing it won't do: schedules and fares. Those change constantly and the operators already publish them. This is a route map. It answers where the boats go, then sends you onward.
